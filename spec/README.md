# 协议一致性套件

这里放的是 [PROTOCOL.md](../PROTOCOL.md) 的机器可读测试向量。

## 为什么需要它

“按规范实现就能互通”这句话只有在能被机械验证时才成立。向量把三个最容易分叉的点钉死：

| 向量 | 钉住的东西 |
|---|---|
| `hlp-hello.json` | 握手签名的**待签字节**（字段顺序、0x00 分隔、ts 的十进制表示） |
| `e2e-hkdf.json` | ECDH 之后的 **HKDF 参数**（salt 的排序拼接方式、info 字符串、密钥长度） |
| `envelope-gcm.json` | AES-GCM 的 **AAD**（就是 header 原始字节）与 nonce 布局 |

## 怎么用

任何实现（不限于 TypeScript）都应该：

1. 读取 `inputs`
2. 按 PROTOCOL.md 的规则算出中间值与最终值
3. 与 `expected` **逐字节**比对（hex 或 base64url 字符串直接相等）

三个向量全部通过，才谈得上“互操作”。

## 建议同时做的两件事

1. **本实现自检**：`npm run spec:check` 跑同一份向量，防止改代码时悄悄改了协议。
2. **第二实现**：CI 里拉一个最小实现（Go/Python，几百行即可），用同一份向量跑一遍，
   再跨语言完成一次真实握手 + 收发一条加密消息。任何一方改了协议而没同步向量，CI 直接红。

第 2 条是硬约束。没有第二实现，规范只是一份愿望清单。

## 版本

向量随协议版本冻结。v1 冻结后，只能新增向量文件，不能修改已有文件的 `expected`。
